# HomeTiles v0.6.4

HomeTiles v0.6.4 is a stability and responsiveness release. It keeps folder,
weather, light, camera, and web-admin interactions responsive during long
sessions, adds separate screensaver brightness, and introduces configurable
local hardware I/O for switches, onboard relays, and DS18B20 sensors.

## Upgrade Order

1. Update **HomeTiles Bridge to v0.6.32** through HACS and restart Home
   Assistant.
2. Update the display to HomeTiles v0.6.4.
3. Open the web admin's **Hardware** tab only if local GPIOs or onboard relays
   should be assigned.

Existing dashboards and hardware assignments are preserved. Camera tiles still
require Bridge v0.6.28 or newer. Bridge v0.6.32 is required only for the new
local hardware entities to appear and migrate correctly in Home Assistant; the
same entities work locally on the panel without the Bridge.

## Faster, More Predictable Interaction

- Caches the current folder and preloads nearby navigation targets so opening a
  folder or returning home does not repeatedly rebuild the complete grid.
- Keeps a bounded cache of navigation pages in PSRAM while protecting the
  internal DMA reserve used by networking and display work.
- Prepares the Weather popup ahead of time and avoids re-rendering its large tile
  background on every tap. Large Weather tiles now keep normal button behavior.
- Restores tile icons and state in stages after page changes instead of leaving
  colored title-only placeholders during longer sessions.
- Keeps media, screensaver, and camera buffers on explicit lifetimes so closing
  one feature does not make later popups progressively slower.

## Light Slider Fix

- Brightness, color, and Kelvin changes continue to be rate-limited to one Home
  Assistant command every 500 ms, avoiding a command for every touch sample.
- The newest value inside that interval is now queued instead of discarded.
- Minimum and maximum slider positions therefore update while dragging, and the
  final value is still sent once more when the finger is released.

This addresses the delayed endpoint behavior reported in
[issue #11](https://github.com/GalusPeres/HomeTiles/issues/11).

## Screensaver Brightness And Idle Handling

- Adds a separate 1-100% screensaver brightness control to the on-device Display
  settings and exposes the same setting through Home Assistant.
- Previews the selected level while dragging, restores normal display brightness
  afterwards, and applies the saved level every time the screensaver opens.
- Keeps an open Camera popup active instead of allowing display sleep or the
  screensaver to cover its stream. The configured idle interval starts again
  after the popup closes.
- Prevents background refresh work from being mistaken for user activity.

## Local Hardware I/O

- Adds a dedicated **Hardware** tab in the web admin with compact, one-line
  assignments and explicit **Save** / **Save & Restart** actions.
- Assigns device-profile-whitelisted pins as local Switch outputs or DS18B20 temperature
  inputs. Output polarity, restart state, and temperature precision are
  configurable where supported.
- Switches respond directly on the display without an MQTT round trip. Local
  entities are immediately selectable in normal and screensaver tiles.
- Adds direct control of both active-high relays on the
  ESP32-P4-86-Panel-ETH-2RO through the existing `waveshare_4b` image.
- Announces local entities to HomeTiles Bridge v0.6.32. Names become readable
  `switch.*` or `sensor.*` entity IDs while stable internal channel IDs keep MQTT
  topics and Home Assistant unique IDs intact.
- Keeps manually renamed Home Assistant entity IDs and safely migrates known
  automatically generated IDs, including numeric collision suffixes used by
  multiple identical panels.
- Moves every device's pin capabilities into its own device profile. The 7, 8,
  and 10.1 inch Waveshare targets have separate definitions; the 4B and 86 Panel
  intentionally share one firmware profile.
- Supports up to eight assignments. DS18B20 uses one sensor per configured
  GPIO/1-Wire bus and requires an external 4.7 kOhm pull-up to 3.3 V.

See [Local Hardware I/O](../hardware-io.md) for setup, pin lists, and electrical
safety notes.

## Web Admin

- Moves the large admin JavaScript and CSS payloads out of C++ source strings
  into generated, gzip-compressed assets with a reproducible stale-asset check.
- Loads shared assets once and reduces the HTML response size and parsing work.
- Adds a bounded folder-data cache, deduplicates refresh requests, and keeps the
  last complete dashboard visible while fresh data is requested.
- Avoids restarting expensive entity and icon loads after every ordinary page
  refresh.

## ESP-Hosted And Network Diagnostics

- Serializes synchronous ESP-Hosted RPC transactions and routes responses by UID
  so concurrent WiFi operations cannot consume each other's replies or fill the
  shared response queue with stale entries.
- Hardens SDIO receive recovery for dropped interrupts, allocation pressure, and
  valid counter wrap values.
- Records additional SDIO counters and whether a Camera stream was active in a
  persistent WiFi-wedge report before a safe restart resets the P4 and C6.
- Keeps the existing safe-restart fallback. The added recovery paths are
  intended to reduce the known lockups but do not claim that every upstream
  ESP-Hosted/C6 fault is eliminated.
- Keeps the experimental CMD53 short-tail receive path out of published images.
  CI builds it separately as a clearly named 8-inch A/B test artifact, while
  every published P4 target uses the a8204 recovery baseline. Promotion remains
  blocked until a 24-48 hour camera soak passes without another wedge.

## Experimental Camera And ESP32-S3 Status

Camera support remains **experimental** on ESP32-P4. Each open panel still starts
its own FFmpeg-backed session on the Home Assistant host, and long camera runs
continue to be an important network stability test.

The Guition ESP32-4848S040 ESP32-S3 image also remains **experimental**. v0.6.4
fixes source-build issues and adds a flash-safe RGB recovery path: on the stock
Arduino SDK the backlight briefly blanks around internal flash writes, then RGB
DMA restarts on VSYNC before the image returns. A community tester reports smooth
page, folder, and popup performance with this fix in
[issue #9](https://github.com/GalusPeres/HomeTiles/issues/9), but broader boot,
OTA, storage, and long-duration hardware testing is still needed. Camera tiles
remain unavailable on this ESP32-S3 target.
